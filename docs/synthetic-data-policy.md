# Synthetic Data Policy

DISU shows people numbers about their own money. A number that looks like a market
observation but was generated by us is the one mistake we cannot recover from
reputationally, and in a consumer-finance context it is arguably a misleading
commercial practice. This document is the repo-wide rule (ROADMAP §2.1).

## The rule

**Any synthetic value that can reach a user must carry a `synthetic: true` flag
through the API layer, and the UI must render it differently from observed data.**

"Synthetic" means any value we produced rather than observed: offline/mock
fallbacks, placeholder quotes, seeded-random series, interpolated history,
estimates, and defaults standing in for missing data.

## Consequences

1. **No hash-derived numbers on user-facing surfaces.** Do not seed a value from
   a symbol, a date, or a user id inside a page or a route handler. If a fallback
   is genuinely needed, it belongs behind a provider that flags what it returns.
   `npm run check:delivery` fails on `charCodeAt(` under `app/dashboard`,
   `app/portfolio`, `app/quant`, and `app/filings-primers` for this reason.
2. **Missing means missing.** When we lack data, render an explicit "not
   available" state. Never substitute zero, never substitute the previous value
   silently, never interpolate a series and draw it as history. A flat `0.00%` is
   a claim about the market; `--` is an admission that we have no reading.
3. **The flag survives every boundary.** A provider that fabricates sets
   `synthetic: true`; the lib layer copies it onto its row type; the route returns
   it; the component reads it and changes what it renders. Dropping the flag at
   any hop is the bug — the UI cannot label what it was not told.
4. **Derived values inherit the flag.** Anything computed from a synthetic input
   is itself synthetic. `computeDayChange()` returns `null` for a synthetic quote
   rather than a number, because a change derived from a fabricated price is
   fabricated.
5. **Production disables fabrication entirely.** `QUANT_MOCK_FALLBACK_MODE=never`
   and `PRIMER_MOCK_FALLBACK_MODE=never` are required in production and enforced
   by `npm run check:delivery:strict`, which runs automatically via `prestart`.

## Where the flag lives today

| Surface | Producer | Flag | UI treatment |
|---|---|---|---|
| Market quotes | `app/lib/market/market-provider.ts` — `PlaceholderMarketProvider` | `QuoteSnapshot.synthetic`, `source: "placeholder"` | Red `placeholder` badge on the price cell (`app/portfolio/page.tsx`); banner on `app/dashboard` |
| Portfolio rows | `app/lib/portfolio/portfolio-positions.ts` | `PortfolioPosition.synthetic`, `priceSource` | As above; excluded from daily-move aggregates |
| Portfolio history | `app/lib/portfolio/snapshot-value.ts` | not written at all | A gap in the series. History is read years later with no badge to see, so a placeholder is excluded and counted rather than flagged, and a day with nothing observable gets no row |
| Day change | `computeDayChange()` | returns `null` | Explicit "Not available yet" panel state |
| Index strip | `app/api/market/indices/route.ts` | `stale`, `source`, `"--"` values | Neutral `--` instead of a coloured 0.00% |
| Quant results | `app/lib/quant/executor.ts` — `createMockQuantResult` | `fallbackMode: "offline"`, `model_path: "mock://quant/offline"` | "Offline mode" label in `app/quant/page.tsx` |
| Primer text | `app/lib/primers/executor.ts` — `createMockPrimerText` | self-labelling body text | Text states it is a placeholder |

## Reviewing a change

Ask: *if this value is wrong or invented, does the screen say so?* If the answer
depends on the reader noticing an absence, the answer is no.
